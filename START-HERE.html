Use one Windows computer for the rehearsal. You’ll create a training database, open the staff interface, and follow one book from delivery to sale. The last section shows how other computers connect when you set up the store.

1. Prepare a training computer

You’ll need Windows administrator access to install software, internet access for installation, and a fresh PostgreSQL instance for training. A PostgreSQL instance runs as a Windows service and can contain several databases. Staff roles are shared across those databases. If the computer already hosts store data or has an existing Bookstore Desk installation, use a separate training PC or instance.

  1. Right-click Bookstore-Database.zip in File Explorer, choose Extract All, and extract it to a folder you can write to. Open the extracted folder containing Start-Bookstore.cmd, package.json, and the sql and web folders. Keep this Explorer window open.
  2. Install the current maintenance release of PostgreSQL 18 for Windows. In the installer select PostgreSQL Server and Command Line Tools. Accept the default installation directory and port 5432 for a fresh PC. Set and keep the password for the database administrator named postgres. Finish the wizard. Stack Builder can be skipped. PostgreSQL Windows download · Installer walkthrough
  3. Install a supported Node.js LTS release using the Windows installer, including npm. Then open a new PowerShell window so it picks up the installation. Node.js download
  4. To open PowerShell in the right folder, click the address bar in your extracted package folder, type powershell, and press Enter. Run the following lines in that window. If you chose a different PostgreSQL installation directory or port, substitute its values below and in Step 4.
$env:Path = "C:\Program Files\PostgreSQL\18\bin;$env:Path"
$env:PGHOST = "127.0.0.1"
$env:PGPORT = "5432"
Test-Path .\sql\001_schema.sql
psql --version
node --version
npm.cmd --version
pg_isready

Checkpoint. Look for True, three version numbers, and accepting connections. If the server is stopped, open Start → Services, find the PostgreSQL 18 service for the training instance, and select Start. Run pg_isready again. Use the same PowerShell window through Step 4.

2. Create an empty training database

Run each command separately. These steps use the name bookstore_training so you can identify the practice database. When prompted for the password for postgres, enter the one from the installer. The terminal hides the password as you type.

createdb -U postgres -T template0 -E UTF8 bookstore_training
psql -X -U postgres -d bookstore_training -v ON_ERROR_STOP=1 -f .\sql\001_schema.sql

The second command creates the book catalog, stock history, audit history, and three staff permission levels. Look for COMMIT at the end. If either command reports an existing database or role, pause and check the instance and database names before proceeding.

psql -X -U postgres -d bookstore_training -c "SELECT current_database(), count(*) AS titles FROM api.catalog;"

Checkpoint. The result should show bookstore_training and 0 titles.

Optional capacity demonstration with 10,000 books

Choose this now, while the training catalog is empty. For a shorter presentation, skip it and use just the one book in Step 5. Run this only in the training database.

psql -X -U postgres -d bookstore_training -v ON_ERROR_STOP=1 -f .\sql\002_demo_10000.sql

On a fresh setup the last line of results shows 10,000 titles and 205,000 copies. Later, search for DEMO-05000 in the staff interface. The book you create in Step 5 will have its own stock code, and its expected quantities stay the same. The seed script refuses a nonempty catalog.

3. Make three staff logins

Run these commands one at a time. If prompted for the postgres password, enter the installer password. When prompted for a new password for the staff user, choose that staff account’s password and enter it again. Keep track of the three passwords for the rehearsal.

psql -X -U postgres -d bookstore_training -v staff=staff_demo_manager -v access=bookstore_manager -f .\sql\create_staff.psql
psql -X -U postgres -d bookstore_training -v staff=staff_demo_clerk -v access=bookstore_clerk -f .\sql\create_staff.psql
psql -X -U postgres -d bookstore_training -v staff=staff_demo_admin -v access=bookstore_admin -f .\sql\create_staff.psql
Account used in the demoWhat to show
staff_demo_managerAdd a title, see its purchasing cost, receive a delivery, and change its selling price.
staff_demo_clerkSee the selling price and stock, search, and record a sale. Purchasing cost is hidden.
staff_demo_adminPerform manager actions, correct stock, and read the history of who made each change.

The postgres account installs and maintains the database. Use the three staff accounts to sign in to the browser.

4. Connect the interface and open it

From the extracted package folder, install the interface’s dependencies once.

npm.cmd ci

Create the local training configuration. The server and browser helper both run on this one PC. In the fresh training folder, paste the entire block into PowerShell, including its first and last lines. It creates web\config.json. If that file already contains store settings, use a fresh extracted folder for training.

@'
{
  "host": "127.0.0.1",
  "port": 5432,
  "database": "bookstore_training",
  "uiPort": 4178,
  "localDevelopment": true
}
'@ | Set-Content -LiteralPath .\web\config.json -Encoding ascii
  1. In File Explorer, double-click Start-Bookstore.cmd. Keep the launcher window open. You can minimize it.
  2. The browser should open at http://127.0.0.1:4178/. If it doesn’t open automatically, type that address in the browser on this computer.
  3. Click 中文 ⇄ English on the sign-in page. Check that the labels change, then choose whichever language you want to present in. Enter staff_demo_manager and its password.

Checkpoint. You should see the inventory dashboard, the guided task form, a cost column, and the + Add a book button. An empty inventory is expected if you skipped the sample dataset.

5. Demonstrate a delivery, a sale, and a stock correction

Allow about ten minutes once setup is complete. Use the book 茶馆 and the unique stock code TEA-DEMO-01 throughout. The table follows that single title, even if you loaded the sample catalog. For each role change, use Sign out beside the account name, then sign in as the next person.

For a second rehearsal on the same database, give the new edition a different title and stock code, or use the new code for all lookups. This prevents selecting a book left over from an earlier rehearsal.

6. Start the next day

  1. Turn on the database computer and check that its PostgreSQL service is running.
  2. On each configured staff PC, open Start-Bookstore.cmd and sign in. The previous inventory is already there.
  3. At the end of a shift, sign out. Closing the launcher ends the local interface session. Leave the central database service running while other tills need it.

7. Use the same inventory from several computers

The training configuration above points back to the computer running it. For live inventory, have the administrator use a dedicated store PostgreSQL instance and the store’s own connection details. Keep training accounts and transactions on the training instance.

  1. On the store server, once. Install PostgreSQL, open PowerShell in the package folder, and use the database creation and schema commands under Install the central database in README.md. They create the production database named bookstore. Provision individual staff logins and assign the appropriate roles. Set up and test backups.
  2. Secure the store network connection. Set the server’s private address, enable TLS with a certificate matching its hostname, and restrict PostgreSQL connections to approved store computers with SCRAM password authentication. Merge the examples under config\ with the server’s actual settings. Apply the settings and verify a staff account can connect using the store CA certificate. PostgreSQL connection rules
  3. On every staff PC. Extract the package, install Node.js LTS, and run npm.cmd ci in that folder. Copy web\config.example.json to web\config.json. Set host to the store server’s certificate hostname, database to bookstore, caFile to the trusted CA certificate file on that PC, and localDevelopment to false. The database port is usually 5432. See UI-SETUP.md for the details.
  4. Two-computer check. In a shared test environment, search the same stock code on two tills. Record a test delivery of one copy on the first, refresh the catalog on the second, and verify the same new count. Staff always open their own local launcher. Each browser uses its own 127.0.0.1:4178 address, and both helpers connect to the same store server.

If something stops you

What you seeWhat to check
psql or createdb is unrecognizedCheck that Command Line Tools were installed. Set the PostgreSQL bin path in the current PowerShell window as in Step 1.
pg_isready reports no responseCheck the Windows PostgreSQL service, host, and port. Port 5432 is the database. Port 4178 is the browser interface.
Database or role already existsIf resuming a completed installation, use its accounts and proceed to Step 4. If unsure, ask the administrator which instance you reached. Starting a fresh rehearsal on another instance preserves existing data.
Launcher asks for configuration or a CA fileFor one-PC training, check that the Step 4 file is named exactly web\config.json. For store access, check the hostname and the CA path supplied by the administrator.
Browser cannot connectKeep the launcher running and use its printed address. If the sign-in page opens but login fails, verify the staff username, password, database name, and database service. Staff cannot sign in with postgres.
Connection dropped after you clicked ConfirmKeep the reference shown. Retry the same confirmation if available. If its outcome is unclear, ask an administrator to check Activity and the stock count before creating a new request.
